# Foshol Doctor

AI-triaged crop-disease diagnosis from photographs and Bangla speech. The product is the
human-in-the-loop: **every case is approved by a field officer before any advice reaches the
farmer.** The model only accelerates triage.

Three crops (rice, tomato, potato), 14 disease classes, one Spring Modulith API, a Python inference
sidecar, and a separate Angular frontend (not in this repository; pin **22.1.5**).

> **No farmer in this system has ever received unverified pesticide advice.**

Remedy rows in the database are labelled **DEMO ONLY**. They are not production agronomy. Do not
quote model-card accuracy figures; the only permitted source is a held-out evaluation produced by
this project.

## Deployment checklist (VM)

This section is the DevOps contract for a virtual machine. It is **not** the laptop workflow.

| | Laptop (`local`) | VM (`dev`) |
|---|---|---|
| Compose file | `docker-compose.yml` | `docker-compose.dev.yml` |
| Spring profile | `local` or `local,demo` | `dev` |
| Java process | host (`./gradlew :app:bootRun` via scripts) | `app` container |
| Sidecar | optional (`docker compose --profile ai`) | always on, **LIVE + Visionary** |
| Persistence | `./.data/` bind mounts | named Docker volumes |
| Secrets file | `.env` (generated by `start-stack.sh`) | `.env` copied from `.env.dev.example` |
| Entry script | `./tools/start-stack.sh` / `./tools/start-live.sh` | **do not use** those scripts |

### 1. Use this Compose file

```bash
docker compose -f docker-compose.dev.yml up -d --build --wait
```

- File: [`docker-compose.dev.yml`](docker-compose.dev.yml)
- Project name: `foshol-dev` (does not collide with the local Compose project)
- Services: `postgres`, `minio`, `sidecar`, `app`
- Network: internal bridge `foshol`
- Published ports: `${APP_HOST_PORT:-8080}:8080` (the API), plus `9000` and `9001` (MinIO S3 API
  and console)
- Postgres and the sidecar are **not** published to the host; the app reaches them by Docker DNS
  (`postgres:5432`, `http://sidecar:8000`)
- MinIO's `9000` **must** be published and reachable by the browser. The API never proxies object
  bytes: it issues a presigned URL, and a presigned URL is signed over its `Host` header, so the
  host inside it cannot be rewritten afterwards. Get this wrong and every case photo fails to load
  while the API itself looks perfectly healthy. See [§3](#3-create-env-on-the-vm).

Do **not** run `docker compose up` without `-f docker-compose.dev.yml` on the VM. That starts the
laptop file (`docker-compose.yml`: bind mounts, Caddy, sidecar behind profile `ai`).

Do **not** run `./tools/start-live.sh` or `./tools/start-stack.sh` on the VM. They start Gradle
`bootRun` on the host, wait on `127.0.0.1`, and bind-mount `${HOME}/.cache/huggingface`.

Caddy is **not** part of the VM stack. It is local TLS for phone `getUserMedia` only. Terminate HTTPS
at the VM load balancer or host reverse proxy if the farmer UI needs a secure context.

### 2. Use Spring profile `dev`

Compose pins this. Do not override it.

```yaml
# docker-compose.dev.yml → app
environment:
  SPRING_PROFILES_ACTIVE: dev
```

| Profile | Where | Sidecar mode | Flyway seed | Dev OTP |
|---|---|---|---|---|
| `local` | laptop | live (host talks to sidecar on `:8000`) | yes | `123456` |
| `demo` | laptop (usually with `local`) | **replay** (wins over `local` if both set) | yes | `123456` |
| `test` | Gradle tests | replay | no | `000000` |
| `dev` | VM | **live** | **no** | **forbidden** |

`dev` is not `local`. `foshol.auth.otp.dev-code` must not be set (`COMMON-SEC-003`). There are no
seeded farmer/officer/admin logins. Create identities through the API (or load them by an
out-of-band process you own).

### 3. Create `.env` on the VM

```bash
cp .env.dev.example .env
chmod 600 .env
# replace every placeholder — then start Compose from the repo root
```

Do not commit `.env`. Do not copy Docker-internal URLs into the laptop [`.env.example`](.env.example).

**Secrets (required)**

| Variable | Constraint |
|---|---|
| `FOSHOL_JWT_SECRET` | ≥ 32 characters |
| `FOSHOL_PHONE_KEY` | 32-byte AES key, Base64-encoded |
| `FOSHOL_DB_PASSWORD` | Postgres password; also used by Spring |
| `FOSHOL_MINIO_ACCESS_KEY` | MinIO root user |
| `FOSHOL_MINIO_SECRET_KEY` | MinIO root password |

**Connectivity (required — Docker DNS names for internal hops; `MINIO_ENDPOINT` is the exception)**

| Variable | Maps to | VM value |
|---|---|---|
| `DB_URL` | `spring.datasource.url` and `foshol.datasource.read-only.url` | `jdbc:postgresql://postgres:5432/foshol` |
| `SIDECAR_BASE_URL` | `foshol.ai.base-url` | `http://sidecar:8000` |
| `MINIO_ENDPOINT` | `foshol.storage.endpoint` | `http://<vm-address>:9000` — **not** `http://minio:9000` |
| `FOSHOL_DB_USER` | `spring.datasource.username` / `POSTGRES_USER` | `foshol` |
| `SPRING_PROFILES_ACTIVE` | Spring | `dev` (Compose also pins this) |

The JVM does not parse `.env` itself. Compose injects the file into the `app` container
(`env_file: .env`). [`application-dev.properties`](app/src/main/resources/application-dev.properties)
resolves `${DB_URL}`, `${SIDECAR_BASE_URL}`, `${MINIO_ENDPOINT}`, `${FOSHOL_DB_PASSWORD}`. Java code
is unchanged.

`MINIO_ENDPOINT` is the one value that is **not** a Docker DNS name. It is the origin the app signs
presigned URLs against, so it is the host the *browser* must resolve — use the VM's own address and
MinIO's API port `9000`. `9001` is the console and does not serve presigned objects. A Docker-internal
name such as `http://minio:9000` leaves the browser with `ERR_NAME_NOT_RESOLVED` on every image, and
because the host is covered by the SigV4 signature it cannot be patched in transit; changing it means
re-presigning. Keep this value in step with the frontend's `MEDIA_OBJECT_STORE_ORIGIN`, which
allow-lists the same origin in its CSP `img-src`, `media-src` and `connect-src` — a mismatch there
blocks the images even when the URLs are correct.

**Sidecar download policy**

| Variable | First boot | Later boots (warm cache) |
|---|---|---|
| `HF_HUB_OFFLINE` | `0` | `1` if the named volume already holds weights |
| `TRANSFORMERS_OFFLINE` | `0` | `1` in lock-step with `HF_HUB_OFFLINE` |
| `FOSHOL_SIDECAR_TORCH_THREADS` | `4` | `4` unless you size the VM otherwise |

Optional: `APP_HOST_PORT` (default `8080`).

### 4. What the VM sidecar is pinned to

Not configurable from `.env`. Hard-coded in `docker-compose.dev.yml`:

- `FOSHOL_AI_MODE=live`
- `FOSHOL_SIDECAR_VISION_BACKEND=visionary`
- Model `VisionaryQuant/5_Crop_Disease_Detection` @ `63080391f7d2bdb331ab356b0d1d9b4b603b3946`
- Crop routes: `rice=rice,tomato=rice,potato=rice,corn=rice,wheat=rice`

ASR (Bangla Whisper) and LaBSE embeddings still load. First boot downloads weights into the
`huggingface-cache` volume. Sidecar health has `start_period: 600s`. `--wait` will block until
`/health` is ready, or fail after that window.

Labels with no taxonomy row stay unmapped and route to `UNDETERMINED` (still queued for an officer).

### 5. Boot, verify, stop

```bash
# from the repository root, with .env present
docker compose -f docker-compose.dev.yml up -d --build --wait

curl -sf http://127.0.0.1:8080/actuator/health
curl -sf http://<vm-address>:9000/minio/health/live     # presign target must be reachable
docker compose -f docker-compose.dev.yml ps
docker compose -f docker-compose.dev.yml logs -f app sidecar
```

The API is ready when `app` is healthy. Flyway applies `classpath:db/migration` on first empty
volume (schema + reference knowledge). It does **not** apply `db/seed`.

Verify the media path end to end once a case exists — a healthy API does not prove it. With a farmer
or officer JWT in `$TOKEN`:

```bash
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://<vm-address>:8080/api/v1/cases/<caseId>/images/<imageId>/url"
```

The returned `url` must begin `http://<vm-address>:9000/foshol-cases/…`. Fetch it with **no**
`Authorization` header — a presigned URL carries its own credentials, and adding a bearer makes MinIO
answer `400 InvalidRequest`. `403 SignatureDoesNotMatch` means `MINIO_ENDPOINT` disagrees with the
host you requested.

```bash
docker compose -f docker-compose.dev.yml stop          # keep volumes
docker compose -f docker-compose.dev.yml down          # keep named volumes
docker compose -f docker-compose.dev.yml down -v       # DESTROYS Postgres, MinIO, model cache
```

### 6. Persistence and images

| Volume | Contents |
|---|---|
| `foshol-dev_postgres-data` | Database (survives `down`, wiped by `down -v`) |
| `foshol-dev_minio-data` | Case photos and audio (`foshol-cases` bucket created by the app) |
| `foshol-dev_huggingface-cache` | Vision / ASR / embed weights |

Images: `app` from [`app/Dockerfile`](app/Dockerfile) (JDK 25 build → JRE 25), `sidecar` from
[`sidecar/Dockerfile`](sidecar/Dockerfile). Postgres is `pgvector/pgvector:pg17`. MinIO image pin
matches the local Compose file.

The VM needs Docker, outbound HTTPS on first sidecar boot (Hugging Face), and enough RAM/CPU for
PyTorch + Spring on one host. JDK 25 on the VM host is **not** required; the app image contains it.

### 7. Safety constraints that apply in `dev`

- No unverified advisory ever reaches a farmer. Killing the sidecar must degrade to
  `UNDETERMINED` + a review task, not a 500.
- Do not train, fine-tune, or swap unofficial model identifiers in Compose without a content-owner
  update to `model_label_map`.
- Do not author dosages, Bangla symptom phrases, or disease copy. See
  [`docs/requirements/CONTENT-OWNERS.md`](docs/requirements/CONTENT-OWNERS.md).

## Architecture

One JVM deployable (`app`) plus one Python sidecar. Postgres (pgvector) and MinIO are the data
plane. There is no message broker.

```
Farmer / officer ──HTTPS──▶ API :8080 (Spring Modulith)
                                │
                                ├── JDBC ──▶ Postgres 17 + pgvector
                                ├── S3 API ──▶ MinIO (foshol-cases)
                                └── HTTP ──▶ sidecar :8000  (vision, ASR, embeddings)
```

The browser fetches case photos, audio and Grad-CAM overlays **directly from MinIO** over presigned
URLs the API issues after an ownership check (`COMMON-SEC-016`). The bucket is never public and MinIO
credentials never leave the API, so MinIO's S3 port has to be reachable by clients as well as by the
app.

Case pipeline:

1. **Identity** authenticates the farmer (phone OTP → JWT) or officer (username/password → JWT).
2. **Intake** accepts 1–3 images (optional ≤30 s audio), quality-gates, stores objects, opens a
   `DiagnosisCase`, publishes `CaseSubmitted`.
3. **Analysis** calls the sidecar (live) or fixtures (replay), maps raw labels through `knowledge`,
   routes by two confidence thresholds, publishes `AnalysisCompleted` even when the sidecar is down
   (`decision_path = UNDETERMINED`).
4. **Review** always creates an officer task. Approve / edit / replace / reject is the only path to
   an `Advisory`.
5. **Notification** delivers the approved advisory (SSE in this repo; SMS/WebPush are stubs).

`analysis` and `knowledge` are separate on purpose: the model can be wrong; the knowledge base is
authoritative. That split is the safety argument (ADR-0001, ADR-0003).

## Modular monolith

Spring Modulith, one JAR, six business modules plus a shared kernel (ADR-0001). Boundaries are a
**failing test**, not a diagram: `ApplicationModules.verify()` and ArchUnit run in `./gradlew build`.

### How modules communicate

Exactly two mechanisms. Anything else fails the build.

| Kind | Mechanism | Example |
|---|---|---|
| Command / query | Call the callee’s published interface in `…/api` | `review` → `AnalysisApi.recordOfficerSymptoms` |
| Fact | Domain event `record` in `common.events`, delivered by Modulith (JPA outbox, republish on restart) | `CaseSubmitted`, `AnalysisCompleted`, `AdvisoryApproved` |

There is no RabbitMQ (ADR-0002). Event records do **not** live in a publisher’s `api` package:
`intake ↔ analysis` and `intake ↔ review` are bidirectional, and publisher-owned events would be
module cycles (`COMMON-ARCH-016`–`018`).

The sidecar is **not** a Modulith module. Analysis reaches it through outbound ports
(`VisionModelPort` and siblings) over HTTP. The sidecar has no database and no authentication;
isolation is the Docker network (`SIDECAR-SEC-001`, `SIDECAR-SEC-002`).

Cross-module persistence: **database foreign keys, never JPA associations**. A foreign UUID is
resolved through the owning module’s API. One writer per table.

### Module map

| Gradle project | Owns | Others may call |
|---|---|---|
| `common` | Enums, `ConfigKeys`, `ErrorCodes`, `Uuid7`, **every domain event record**. No Spring beans, no logic. Modulith shared module. | — (everyone depends on it) |
| `modules/identity` | Farmer, FieldOfficer, phone auth, JWT | `FarmerLookupApi`, `OfficerLookupApi` |
| `modules/intake` | `DiagnosisCase`, images, audio, idempotency, status | `CaseIntakeApi`, `CaseIntakeChannel`; events `CaseSubmitted`, `CaseStatusChanged` |
| `modules/analysis` | Orchestration, sidecar ports, label mapping, `ConfidenceRouter` | `AnalysisApi`; events `AnalysisCompleted`, `AnalysisFailed` |
| `modules/knowledge` | Crop, Disease, Symptom, Remedy, `model_label_map`, pgvector matcher | `KnowledgeQueryApi`, `SymptomMatchApi` |
| `modules/review` | Officer queue, claim/approve/edit/replace/reject, `Advisory` | `ReviewSubmissionApi`; events `AdvisoryApproved`, `AdvisoryRevised`, `CaseRejected` |
| `modules/notification` | Delivery, SSE, channel registry | `NotificationPort`, `NotificationChannel` |
| `app` | Spring Boot entrypoint, `application*.properties`, all Flyway migrations | — (the deployable) |
| `sidecar/` | FastAPI vision / ASR / embed (separate process) | HTTP `/v1/*` |

Allowed compile-time edges (build order): `common` → (`identity`, `knowledge`) → `intake` →
`analysis` → `review` → `notification`. Cycles are forbidden (`COMMON-ARCH-011`).

### Inside each business module

```
com.rootcause.foshol.<module>/
  api/              the ONLY package other modules may import
  domain/           aggregates, VOs, specifications, exceptions — no Spring, JPA, or Jackson
  application/
    command/        commands + one handler each
    query/          queries + handlers + read models
    port/           outbound ports
  infrastructure/   JPA, adapters, `@ApplicationModuleListener`
  web/              controllers: bind, delegate to one handler, map the result
```

Layering is `web → application → domain` (`COMMON-ARCH-003`). Commands and queries are separate
classes (`COMMON-ARCH-005`).

## Conventions

Enforced by ArchUnit, Modulith verify, and code review.

- Records for every DTO, command, query, event and read model.
- Constants in `com.rootcause.foshol.common` for event names, error codes, config keys, enums.
- Imports, not FQCNs, in method bodies.
- No business logic in a controller; no Spring/JPA/Jackson in `domain`.
- No Java preview APIs (`StructuredTaskScope` is forbidden on JDK 25). Use virtual threads via
  `Executors.newVirtualThreadPerTaskExecutor()` with `CompletableFuture` and an explicit deadline.
- Hand-written mappers only.
- No model training or fine-tuning. Load pretrained weights by configured identifier (ADR-0008).
- No agricultural content authored by agents. Wrong dosage is harm, not a bug.
- British spelling in prose.

API surface: [`docs/openapi/foshol-api.yaml`](docs/openapi/foshol-api.yaml). Additive bilingual
catalogue fields may be added; do not break required fields.

## Local development

Laptop only. JDK 25, Docker, `curl`.

| Piece | Role | Address |
|---|---|---|
| Postgres 17 + pgvector | cases, knowledge, identities | host **5434** → 5432 |
| MinIO | `foshol-cases` | **9000** / console **9001** |
| Spring (`:app:bootRun`) | HTTP API | **8080** |
| Sidecar | optional live inference | **8000** (`--profile ai`) |
| Caddy | optional HTTPS for phones | **80** / **443** |

Postgres and MinIO persist in `./.data/`. `docker compose down` / `down -v` do **not** delete that
directory (`rm -rf .data` does).

**Replay (default, no sidecar):**

```bash
./tools/start-stack.sh          # profiles local,demo — fixtures, seeded logins
./tools/call-api.sh             # numbered client; session in tools/.run/api-session.json
```

Ctrl-C on the stack script detaches; Docker and Java keep running. Stop the API with
`kill $(cat tools/.run/app.pid)`.

Seeded logins (`local`/`demo` only): farmer `+8801711111111` OTP `123456`; officer `officer` /
`password`; admin `admin` / `password`. District aliases: `officer-{code}` / `admin-{code}`.

**Live sidecar (laptop):**

```bash
./tools/start-live.sh              # ViT
./tools/start-live.sh visionary    # EfficientNet-B3 — mutually exclusive with ViT
```

Uses Compose `profile: ai`, then Spring profile `local` (not `demo` — `demo` forces replay). First
run downloads weights into `~/.cache/huggingface`.

Do not combine `local` and `demo` when you want live inference.

**Wipe laptop data:** `docker compose down && rm -rf .data`, then `./tools/start-stack.sh`.

**HTTPS for a phone on the LAN** (voice capture needs a secure context; not required on the VM
stack):

1. `mkcert -install`
2. `mkdir -p deploy/certs && mkcert -cert-file deploy/certs/local.pem -key-file deploy/certs/local-key.pem "$(hostname).local" 192.168.x.x localhost`
3. Trust the mkcert CA on the phone
4. `docker compose up -d caddy` → `https://<lan-ip>/`

Client-isolated Wi-Fi: use a tunnel (`cloudflared` / `ngrok`).

The farmer UI re-encodes photos. Replay keys vision by SHA-256 of **uploaded** bytes, so a browser
capture of a demo JPEG will miss the fixture (`UNDETERMINED`, still queued). Byte-exact uploads from
`./tools/call-api.sh` on `local,demo` still hit replay fixtures. For PRIMARY from the UI, use live
sidecar.
